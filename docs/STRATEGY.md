## 3. 이론적 토대 — 점근선/조림 (왜 병목이 Sense이고 Author가 아닌가)

**"AI는 점근선, 조림이 상한선."** AI 출력은 0→1이 아니라 인간 조림(감→측정·재현)의 점근선이고, **조림 루프의 정밀도가 AI 출력의 천장을 결정**한다. 조잡한 조림 → 멀찌감치 멈춤; 정밀한 조림 → 실사용상 구분불가까지 근접. `[external, durable]`

함의 1 — **fal 모델 = 점근선, 우리 레시피 조림 = 천장.** "최고 모델 고르기"가 아니라 각 모델의 점근선을 우리 조림이 얼마나 끌어올리는지의 문제. 조잡한 조림의 좋은 모델 < 정밀한 조림의 평범한 모델. `[external → thesis]`

함의 2 (가장 결정-관련) — **외부 조림 vs 내부 조림 = 해자 유통기한 테스트:** `[external, durable]`
- **외부화된 조림** = prompt_template·Prompt Enhancer의 craft 토큰. 재사용 가능하나 **점근선 수렴 압력 노출** — 모델이 좋아지면 기본능력에 흡수됨. **감가자산.** (Higgsfield의 prompt-assembly 해자도 영구 복제불가가 아니라 *모델이 결국 흡수*.)
- **내면화된 조림** = 사용자의 한국 셀피 트렌드 감/Sense. **모델이 학습할 통로 자체가 없음. 적립자산.**
- → 이것이 §2의 "병목 = Sense+Learn, Author 아님"의 이론적 정당화. **Prompt Enhancer는 단기 lead-time용 감가자산, 진짜 적립은 Sense 체계화.**

함의 3 — **세공력은 꼬리 판별자를 요구한다.** 꼬리 판별자는 "AI 분포에 의식적 저항 + 다른 입력 풀 유지"해야 한다(눈이 AI 출력에 동질화되면 안 됨). `[external, durable]`

함의 4 — **딸깍 vs 세공.** "AI 디자이너 가치 = 딸깍 환상의 해체 + 세공이라는 답." = 우리 "non-slop / authenticity-sense" 포지셔닝의 출처. `[external → thesis]`

함의 5 — **트렌드-처리 능력의 삼분 (어디에 *인간* 시간을 쓰나).** 사용자 자산 = early-sense → structure → output 루프(= 조림 그 자체). 셋의 내구성이 다르다: `[external → thesis]`
- **early-sense (일찍 파악)** — 영구 해자. 내면화 조림 + 신선한 입력 풀 + 꼬리 판별자 취향. 모델이 학습할 통로 없음.
- **structure (분석/구조화)** — 감가. AI가 이미 트렌드 구조화를 잘함(외부 조림). 단 early-sense와 *분리불가하게 엮인 만큼만* 해자.
- **output (결과물)** — 렌트. fal이 만듦.
- → **대체불가 인간 시간은 early-sense + 입력 풀 신선도에**, structure·output은 시스템/AI에 위임. "나는 트렌드를 구조화한다"를 해자로 착각 금지(AI에 잠식).

## 6. 방향 — 콘텐츠/바이럴 VTON (성장 엔진) × 트렌드-큐레이션 (해자)

`[decision: 방향 확정 (2026-06-27 전략 대화)]` `[validation pending: 아래 "검증 대기"]`

**제품 (1차, 사용자가 보는 것):** 사용자가 *주체* — 입고 싶은 특정 의류/뷰티를 고르면 앱이 *그걸 착용한 인스타그래머블 사진*을 만들어줌(가상 피팅 VTON). 가치 = 재미·자기표현·**공유**. **1차 목표 = 콘텐츠/바이럴 성장**(커머스 아님 — 커머스는 하류 수익화). 현 vanity 빌드 = 이 VTON 창작 도구의 토대로 재사용.

**핵심 구분 — 바이럴은 *성장 엔진*이지 *해자*가 아니다.** 유행 필터 앱이 떴다 죽는 이유: 밑에 해자가 없으면 경쟁자가 같은 파도를 베낌. → 콘텐츠/바이럴은 *수단*(성장), **그 밑에 해자가 따로 있어야** 스파이크 후 생존.

- **성장 엔진 (앞) = *계정-무관* 제품 바이럴 (k>1).** 콘텐츠/바이럴 VTON: 공유할 사진 → *낯선 사람* 유입 → 또 공유. **창업자 의존은 점화 *방법*이 아니라 *제품의 k*가 정함** — k>1이면 15만은 공짜 옵션 스타터(의존 아님), k<1이면 *어떤 점화도* 못 살림(밑 빠진 독). 그래서 15만을 *성장 엔진으로 안 기댐*(§2 강등). craft(사진 퀄=`fal_eval`)가 *핵심 제품 가치* — 공유할 만큼 자연스럽고 예쁘지 않으면 루프가 안 돎(Author/craft 재격상).
- **해자 씨앗 (a) — 창업자 트렌드-큐레이션/early-sense:** 매주 신선한 룩으로 *남이 못 따라오는 속도/감*. 내면화된 조림(§3) = 뿌리. **있음**(15만 영수증). 단 *당신-의존* → 단독이면 (1) 라이프스타일.

### 7-A. "트렌드"의 정의

**트렌드 vs 필터 = 시의성(반감기).** 정적·상시·에버그린 = 필터(커머디티, 해자 없음 — Meitu/Higgsfield의 "스타일"). 우리를 *트렌드*로 만드는 단 하나는 **"지금" 주장 + 반감기.** 시의성이 셋을 동시에 만듦: ① 해자(일찍 감지 = early-sense §3) ② 재생성(만료→재방문, 리텐션 갱신) ③ 차별화(정적 필터와 갈라짐). `[thesis]`

**두 층 (룩 + α):** `[thesis]`
- **룩 레이어** — 몸에 걸친 것(발레코어·올드머니 등 스타일링/미감).
- **포맷 레이어 (α)** — *게시물로서의* 편집: 텍스트 삽입·매거진 레이아웃·필름 날짜스탬프·콜라주. = *올렸을 때 알고리즘이 띄워주는 완성 포맷.* IG가 raw 업로드보다 편집된 게시물을 부스트하는 경향이 근거.
- α가 결정적인 이유: payoff의 닻을 **vanity("나 예쁘게 나왔다", 사적·커머디티)에서 알고리즘 도달("올리면 도달이 뜬다", 성과·측정가능)으로** 옮김 → ④를 vanity 함정에서 끌어냄. 또 창업자 엣지를 "패션 취향"에서 "현직 인플루언서의 *플랫폼-메타* 감각"으로 격상(더 인사이더·더 빠른 반감기).

**floor vs differentiator (예쁨의 위치):** `[thesis]`
- **FLOOR = 예쁨** (인스타 미감 + 정체성 보존 + AI티 없음 + 한국인 적합). rented·돈으로 살 수 있음. **못 넘으면 죽고(Meitu 바닥), 넘어도 안 이김**(Meitu도 예쁨). "거기선 이기려 말고 지지만 않으면 됨."

**단위 = 룩** (아이템 = 하류 분해[(d) 커머스], 미감-only = 배제[*필터*로 추락, 참여성 죽음]). **α 경계:** 프리폼 편집기(Canva/VSCO) 아님 — operator가 큐레이션한 *"이번 주의 게시물 포맷"* 템플릿. 룩과 똑같은 큐레이션 논리를 포맷에 적용. `[thesis]`

## 10. 제품 형태 확정 — 내 옷 × 트렌드 (2026-07-02)

`[decision: 확정 (2026-07-02 전략 대화)]` — §6 방향·§7 정의를 *제품 형태*로 한 단계 더 구체화. §6-§9 프레임 **유지**, 아래는 그 안에서의 형태 결정.

**결정 체인 (B → ii → ii-a):**
- **형태 = B (콘텐츠 제품 + 내 옷을 입력, *허브 아님*).** "내 옷을 찍으면 생성"은 옷장-중심 재정렬(A)이 아니라 트렌드-콘텐츠 제품(§6) *안의 입력 모드*. switching-cost 해자(옷장=투자 허브)는 *의식적으로 안 켬* — 커머디티 옷장-앱 카테고리(에이클로젯·Whering·Doppl) 진입 비용 회피. `[decision]`
- **중심도 = ii (공동 주연).** 내 옷 입력은 곁가지 옵션이 아니라 *일상 루프의 기본 입력*: **"내 실제 옷 × 이번 주 operator 트렌드+포맷."** 이유: (b) 행동/선호 데이터·(d) 커머스 기질은 내 옷을 *routine*으로 써야 스케일로 적립(가끔 옵션이면 그 업사이드가 안 옴). `[thesis]`

**한 줄 형태:** 제품 = 트렌드-콘텐츠 VTON 앱(§6-§9). 일상 루프 = **"내 실제 옷 × 이번 주 operator-큐레이션 트렌드+포맷"** — operator는 트렌드/포맷(owned 해자), 사용자는 옷(개인화·(b)·(d) 기질).

**SSoT 갱신:**
- **§7-A 단위=룩 → 재해석(supersede 아님):** 큐레이션 단위 = 룩+**포맷 α**, 사용자 옷 = 거기 렌더되는 원재료. 옷이 사용자 것이 된 순간 operator 가치는 *어떤 옷이냐*에 못 있고 *어떻게 연출·포맷되냐*로 갈 수밖에 없음 → **§7-A의 포맷 레이어 α가 *주* differentiator로 격상**(payoff 닻 vanity→도달, 이미 §7-A가 가리킨 방향). `[thesis]`
- **§8.1 아이템 소싱 fork → 닫힘:** 업로드 vs 카탈로그 = **둘 다, operator 카탈로그 우선(해자) + 내 옷 routine 입력.**
- **§9-D SKU=렌트 → 유지 + 바운디드 충실도 축 추가:** "내 옷이 그 옷처럼 나옴"은 필요하나 = *네 옷을 새 연출/포맷에 충실 렌더*(good-enough 렌트)지 프런티어 SKU-매칭(ii-b가 요구하던 것) 아님. 충실도 디스크리미네이터(§9-D⑥)에 **의상 축**이 이 바운디드 형태로 추가(정체성/naturalness 축과 별개). `[thesis]`

### 10-A. 옷 메타데이터 — 3분류 (2026-07-02 후속)

- **③ = §10-A 원탭 칩과 동일 단계의 두 출구** — 별개 기능이 아님: 확신 높으면 자동 주입, 낮으면 칩. 오식별 리스크는 확신도 게이트(②의 자기일관성 + ③의 사용자 확인)로 흡수.
- **① 옷 DB의 세 갈래 적립:** ⓐ 운영자 트렌드 시딩(주간 큐레이션의 자연 확장 — 트렌드 레시피와 같은 리듬으로 자람) ⓑ 사용자 칩-확인 환류(확인 행위 = 라벨링 데이터; moat (b) 행동 데이터의 옷-속성 확장) ⓒ (나중) 커머스 카탈로그 — 이 DB가 곧 **(d) 커머스 SKU 레일의 선행 투자.** 초기 커버리지는 낮음(옷장은 롱테일) — ②③이 받치고, 시간이 갈수록 ① 적중률 = 해자 깊이. `[thesis]`
- **저장 경계 (불변식 #1 인접):** DB·환류에 저장하는 건 **텍스트 프로필뿐, 옷 사진 서버 저장 금지**(zero-PII 기조 유지; 사진 저장은 별도 명시 결정 전까지 없음 — "옷장 경계" 파킹 유지).
- **④ 외부 검색은 최후 수단이자 (d) 국면 도구** — 지연으로는 더 이상 탈락하지 않으나(위 ruling), 오식별 게이트 + 제3자 사진 전송 운영자 승인 두 게이트는 유효.

## 유지보수 노트

- **add/trim 규율:** 새 증거(eval 결과·코드 변경·트렌드·모선)가 나오면 해당 절을 갱신하고 태그·검증일을 함께 갱신. 반증된 `[thesis]`는 깎는다. 흡수된 `[external]`은 유통기한 만료로 표시.
- **코드가 진실:** `[ground-truth]` 항목은 인용 전 재검증(파일은 이동·변경됨). 이 문서가 코드와 충돌하면 코드가 이긴다 ([[mothership-vs-project-truth]]).
- **모선과의 관계:** 이 문서는 *이 프로젝트*의 정체성·방향을 정한다(모선 write-back 아님). 모선은 도메인 지식·why를 빌리는 곳이지 current-state 출처가 아니다.
