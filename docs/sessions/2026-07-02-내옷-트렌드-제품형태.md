# 2026-07-02 — 피봇 정련: 내 옷 × 트렌드 (제품 형태 확정)

## 논의
"내 옷을 찍으면 옷 이미지 생성"을 피봇 방향으로 세부화. 큰 방향(제품 정체성)만 먼저 닫고, hook/펀넬 디테일은 파킹. §6-§9 프레임 위에서 *형태*를 결정 → STRATEGY.md §10으로 박음.

## 옵션 저울질
- **출력이 뭐냐:** A(내가 입은 컷=VTON 콘텐츠) / B(옷만=옷장·리세일 유틸) / C(옷장 빌드→그 옷으로 콘텐츠) → 초기 **C**. (문자 그대로 "옷 이미지"=B지만 피봇 맥락은 콘텐츠.)
- **제품 무게중심:** A(옷장-중심 제품, switching-cost 해자) vs B(트렌드-콘텐츠 제품 + 내 옷을 입력) → **B.** A는 보상(switching-cost, 현 전략 미사용 축)도 크나 붐비는 옷장-앱 카테고리(에이클로젯·Whering·Doppl) 진입 + SKU 충실도 복귀 비용. **A 의식적으로 버림.** (C의 "진입=유틸/옷장"도 B가 supersede — 진입은 콘텐츠, 내 옷은 그 안 입력.)
- **내 옷 중심도:** (i)가끔 옵션 vs (ii)공동 주연 → **ii.** (i)면 (b)/(d) 옷장 데이터가 스케일로 안 쌓여 "입력 옵션 하나" 이상 안 됨.
- **operator가 뭘 큐레이션:** ii-a(포맷/연출 중심, 옷=원재료) vs ii-b(완성-룩 큐레이션 + 사용자 옷 치환) → **ii-a.** ii-b는 트렌드가 옷-정의라 내 옷과 싸우고 SKU 프런티어 무게 재진입.
- **§7-B hook 재고:** 사용자가 열자 제안 → **파킹**(큰 방향 닫은 뒤 다음 세션). 단 원리("hook=핵심가치 첫 입, 즉시반환, =공유")는 살림 — 진단 퀴즈를 죽인 건 *가치 앞 세금*이라서. 옷을 hook에 넣어도 "옷장 등록"(세금=탈락) 아닌 "아이템 한 장 즉시변신"(통과) 형태여야.

## 왜 / 교훈
- **피봇이라 부른 게 실은 정련(B).** "내 옷 찍어 생성"은 §6-§9를 뒤엎는 게 아니라 그 안의 입력 모드 — 큰 방향은 이미 §6-§9에 서 있었고, 이번은 *형태*를 박은 것.
- **owned 해자를 지키는 축 = 포맷/연출(α).** 옷을 사용자에게 넘기면 차별화가 옷에서 못 옴 → α(operator 큐레이션)로 갈 수밖에 없고, 그게 §7-A가 이미 가리킨 방향(vanity→도달 payoff 이동)과 수렴. "옷장-앱 자체는 차별화 0"이 A를 버린 핵심 근거.
- **(b)/(d) 업사이드는 routine 사용에 조건부.** 내 옷 입력이 가끔이면 옷장 데이터·커머스 기질이 스케일로 안 옴 → ii 선택의 근거.
- **트리거(이 회의록):** 큰 방향(형태 결정)이 *닫히는 순간* 에이전트 in-turn 플래그 + 사용자 pre-close 승인("추천대로 가자"). SSoT(§10)엔 결정만, 버린 길(A·ii-b)과 왜는 여기에.
