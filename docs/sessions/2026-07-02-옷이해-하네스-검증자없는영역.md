# 2026-07-02 (2차) — 옷 이해 하네스 · 검증자 없는 영역 ② · M1 백엔드 출고

## 논의
같은 날 §10 세션의 후속 3갈래: ① 피봇 마일스톤 1(백엔드 seam) 코딩·머지, ② "검증자 없는 영역" 논의(특히 ②번 = 취향/품질 판단 — "나조차 검증자가 아닐 수 있음"), ③ eval 확정 *전에* 생성 하네스부터 논의(사용자 지적: eval은 프로덕션 하네스의 실제 입력 분포를 샘플링해야 함).

## 옵션 저울질
- **하네스 형태:** A(동기 검색-식별) / B(점진 강화+옷 캐싱) / C(VLM 서술만) → 에이전트는 hook 지연 세금을 근거로 C 추천 → **사용자 ruling이 그 근거를 철회시킴**: "hook보다 생성 품질이 더 중요. hook은 매력적으로 재설계하면 됨." 지연은 더 이상 탈락 사유 아님.
- **"식별 = 검색"으로 좁히지 않기 (사용자):** 검색 외 방법들 — 구조화 추출(VLM 칸 채우기), 자기일관성 검사, 원탭 칩 확인(§10-A와 동일 단계), 내부 어휘 매핑, 옷 단독 재생성, 외부 검색. + **사용자 추가: 미리 옷 정보를 데이터화(내부 옷 DB) — 추론이 아니라 대조**, 시간이 곧 해자 깊이.
- **설계의 핵심을 방법이 아니라 산출물 계약으로:** "옷 프로필(칸+확신도)"을 고정하면 해석기는 갈아끼움 가능 → 계층형(①DB대조→②구조화추출→③칩→환류, 나중 ④검색)으로 수렴.
- **검증자 없는 영역 ② 대응책 합의:** 블라인드 채점 모드(모델/출처/비용 라벨 숨김+셔플), test-retest 중복 셀(~10%, 자기-드리프트 측정), 프롬프트 저작권을 운영자로(에이전트-저작 프롬프트 오염 방지), 앵커 세트. IG 도달 마이크로-테스트는 파킹.
- **옷 단독 생성 = stage-0 (사용자):** "인물에 입히기 전에 옷 단독 이미지가 잘 생성되어야" → eval 앞단 프로브로 합의.

## 왜 / 교훈
- **판단 슬롯이 실제로 작동한 세션.** 에이전트의 C 추천(지연 세금 논거)을 운영자 ruling이 뒤집음 — 그리고 그 ruling이 전략 자체 논리(§7-C floor 우선, §7-B payoff 원리)와 정합함을 에이전트가 영수증으로 확인. 방향 판단은 자동화 안 됨의 실례.
- **"방법"이 아니라 "계약"을 고정하는 설계.** 옷 프로필 계약을 고정하니 검색/DB/VLM 논쟁이 "언제 어떤 해석기를 켜나"라는 진화 문제로 바뀜.
- **eval은 하네스의 하류.** 사용자가 순서를 바로잡음 — 프로덕션 입력 분포(강화된 프롬프트)가 정해져야 eval이 그걸 샘플링할 수 있음.
- **트리거(이 회의록):** 하네스 스레드가 닫히는 순간("이대로 가자") 에이전트 in-turn 플래그.
